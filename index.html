Section 4

4. Vulnerability Remediation & System Hardening Blueprint

Defensive engineering matrix pairing each security weakness exploited during the lab with industry-standard mitigation strategies.

Case A

Exposed Staging Backups Under Webroot

Exploitation Context: Plaintext system keys and credentials left within unlinked web deployment paths assume attackers will not run brute-force path profiling.
Remediation Strategy
Permanently remove sensitive code elements from the accessible web server directory layout. Enforce systemic folder listing restrictions within global configuration modules: # Prevent unauthenticated directory file mappings globally Options -Indexes
Case B

World-Writable Automation Tasks (Cron Script Abuse)

Exploitation Context: Assigning open group write permissions (777) to operational scripts parsed by system-wide background agents enables arbitrary code execution injection.
Remediation Strategy
Revoke global write access. Enforce standard restrictive configuration control mappings so that only authorized owners or administrative contexts can alter file operations: chown root:root /opt/scripts/cleanup.sh chmod 750 /opt/scripts/cleanup.sh
Case C

Unsafe SUID Binary Assignments

Exploitation Context: Leaving custom binaries with active SUID bits allows non-root users to inherit system-level permissions. If these files can be manipulated into spawning sub-processes, full root compromise occurs.
Remediation Strategy
Strip the SUID bit from custom utilities. Instead, grant explicit system capabilities (setcap) or implement highly restricted, parameters-validated authorization rules inside the system sudoers file structure: # Remove execution impersonation privileges completely chmod u-s /opt/vulntool
